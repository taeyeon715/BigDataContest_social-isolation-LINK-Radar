# EDA-6 사전 경보 재평가

> **평가 버전: rules-v1.1 당시 기준(z −2.5, 7일 중 3일).** 본문의 736/817(90.1%)은 이 기준의 합성 하락 실험 결과로 보존합니다. 현행 v2.0의 z −2.0·7일 중 4일 결과는 [M3 임계값 비교](../m3_모델링결과/README.md)의 753/814(92.5%)이며, 기준 선택의 별도 LINK-Sim 평가는 [R-3 4절](../r3_규칙개정/README.md)을 참조하세요. 모두 실제 고립 발견 정확도와 구분합니다.

[← 전체 리포트 목록](../README.md)

EDA-5의 경보 성능은 6개월 전체로 평소 값을 만든 **사후 계산**이었습니다. 그래서 '그날 미리 알 수 있었나'를 보여 주지 못합니다.
여기서는 날짜 t의 판정에 **t까지의 자료만** 씁니다. 같은 규칙을 M1 모델·R-1 등급 규칙·에이전트가 다시 쓰도록 `src/bigcontest/signals/alarm.py`에 두었습니다.
주요 내용: 연휴 뒤 회복을 세 가지로 나눔, 기준일 카드와 사후 목록 분리, 지연 설명, 보류 회계, '둘 중 하나' 세 값 조합, 입력 계약.

**용어**

| 용어 | 뜻 |
|---|---|
| absolute 경로 | 코호트 결제가 그 코호트의 평소보다 실제로 줄었나 |
| local 경로 | 같은 날 도시 전체 변화(`city_shock`)를 빼고도 그 코호트만 벗어났나 |
| city_shock 경로 | 도시 코호트들의 공통 변화 자체에 같은 창 규칙을 적용한 도시 단위 경보 |
| alarm_date | 경보를 판정한 날 = 7일 창의 **마지막 관측일**. 창은 `window_start`~`window_end` |
| 보류 | 점수나 경보를 만들 수 없어 판정하지 않은 날(학습 기간 부족, 창 안 유효 점수 부족, MAD=0, 미공급 등). 경보 없음(0)과 다름 |
| 배경 경보율 | 실제 자료에서 아무것도 넣지 않았을 때 경보가 난 비율. 그 기간에 진짜 이상이 없었는지 모르므로 **오경보율이 아님** |
| 오경보율 | 이상이 없도록 만든 합성 시계열에서 경보가 난 비율 |
| 순증 경보율 차이 | 같은 (도시, 연령, 성, 시작일) 쌍에서 '주입했을 때 경보율 − 주입 안 했을 때 경보율'. 확률 차이라 **%p**로 적고 전이 표와 함께 봄 |
| 사후 목록 | 자료 끝(12/31)까지 본 뒤 정리한 경보 목록. 회복 검토가 경보일 뒤 자료를 씀 |
| 기준일 카드 | 그날(as_of)까지의 자료만으로 다시 계산한, 그날 화면에 보였을 경보 상태 |

## 1. 방법

- 자료: 카드 데이터2, 같은 시도 거주 고객, 본사등록 업종 제외. 코호트 = 도시 × 연령(20대~80대+) × 성 = 28개, 184일
- 평소 값(기대값): t보다 앞선 **같은 요일** 값의 평균(최근 56일, 공휴일 제외). 잔차 e(t) = log(결제+1) − 기대값
- 점수: e(t)를 t보다 앞선 56일(공휴일 제외)의 중앙값·MAD로 나눈 robust z. 처음 28일은 학습 기간이라 평가하지 않음
- 경보: alarm_date = t, 창 [t−6, t]에서 z < -2.5인 날이 3일 이상. 창 안에 점수가 있는 날이 5일 미만이면 보류
- 두 경로: absolute(e 자체), local(e − 같은 날 같은 도시 코호트 e의 중앙값 = `city_shock`). 도시 공통 변화는 버리지 않고 `city_shock` 신호와 도시 경보로 따로 저장
- '둘 중 하나' 경로는 세 값 논리입니다: 한 경로라도 1이면 1, 두 경로 모두 판정되고 0이면 0, 나머지((0, 보류)·(보류, 보류))는 보류. 한 경로만 본 0을 '경보 없음'으로 세지 않습니다.
- MAD가 0이거나 과거 관측일이 부족하면 작은 값을 더해 억지로 점수를 만들지 않고 NULL + 보류 사유를 남깁니다.
- 같은 코호트에서 7일 안에 다시 울린 경보는 한 건으로 묶습니다(중복 제거).
- **입력 계약**: 점수를 만들기 전에 날짜 정렬·중복 없음·하루 간격 연속·값이 유한하고 음수 아님을 검사합니다(`check_panel_input`). 이번 입력(184일 × 28코호트)은 통과했습니다. 빈 칸(NaN)은 '미공급'으로 받아 그날을 보류하고 0건으로 바꾸지 않습니다.
- **카드 0건 가정**: 카드 `daily()`는 결제 행이 없는 (날짜, 코호트)를 0건으로 채웁니다. 이번 표에서 0인 칸은 0개입니다. 제공기관이 '거래 0'과 '미공급'을 구분해 주는지 확인하기 전까지 이 0은 가정입니다.
- **강수 자료**: ASOS 행은 있는데 강수량이 빈 날은 기상청 정의대로 무강수(0)입니다. 행 자체가 없는 날은 무강수가 아니라 '모름'으로 둡니다(이번 자료에서 빠진 행 0개).

### 공휴일 반증 규칙

공휴일 앞뒤 1일에 걸린 창은 '반증 검토 시작'일 뿐 바로 기각하지 않습니다. 대상 코호트의 공휴일 기대값(창 이전 공휴일의 local 잔차 평균), 도시 공통요인, 연휴 뒤 3일(공휴일 아닌 날)의 회복을 봅니다. 회복은 세 가지로 나눕니다.

| 칸 | 뜻 |
|---|---|
| `recovery_abs` | 대상 코호트가 **평소 수준**으로 돌아왔나 (absolute 잔차 평균 ≥ −0.05) |
| `recovery_local` | 도시 대비 **추가 이탈이 없나** (local 잔차 평균 ≥ −0.05). 도시 전체가 계속 낮아도 '추가 이탈 없음'일 수 있음 |
| `recovery_common` | 도시 공통요인이 돌아왔나 |

| 반증 결과 | 조건 | 결정 시점 |
|---|---|---|
| 통과 | 공휴일 기대값·공통요인을 빼도 경보 조건이 남음 | alarm_date |
| 기각 | 설명되고, 연휴 뒤 **평소 수준으로 회복**했고 도시 대비 추가 이탈도 없음 | 회복 확인일 |
| 확인 필요 (도시 공통 변화) | 도시 대비 추가 이탈은 없지만 연휴 뒤에도 평소보다 낮음. 다른 코호트도 함께 낮다는 설명일 뿐 **공휴일이 원인이라는 증거가 아님** → 기각하지 않고 `city_common_flag`로 남겨 원인·접근성 확인 | 회복 확인일 |

## 4. 짝지은 하락 주입 실험 (코호트 하나)

(도시, 연령, 성, 시작일) 목록을 **한 번만** 뽑아 고정했습니다(코호트마다 시작일 30곳, 모두 840쌍). 같은 목록에 대조(주입 없음)와 10/15/20% 하락 주입을 모두 적용합니다. 시작 전날 이미 경보 중이던 쌍은 평가에서 빼고 따로 셉니다.
- 주입: 시작일부터 14일 동안 **대상 코호트 하나**의 결제건수에 (1 − 하락률)을 곱함. 기대값·MAD는 과거 자료만 쓰므로, 주입된 날이 쌓이면 뒤쪽 기준값도 같이 내려갑니다(실제 운영과 같음).
- 공휴일 제외는 **주입 구간 14일(앞뒤 1일 포함)에만** 적용했습니다. 첫 판정 창에 들어가는 시작 전 6일은 제외 조건이 아닙니다. 그 6일에 공휴일 앞뒤가 걸린 쌍: 104쌍 / 840쌍.
- 성공(탐지): 대조에서는 14일 안에 경보가 없었는데(0) 주입하면 경보가 난(1) 쌍. 탐지율 = 0→1 / (0→0 + 0→1). 대조에서도 울린 쌍(1→1)은 탐지로 세지 않습니다.
- 지연: 시작일부터 첫 경보의 alarm_date까지 일수. 새 하락만으로 낮은 날 3일이 모두 쌓이면 최소 2일이지만, **시작 직전 창에 이미 낮은 날이 있으면 0~1일도 가능**합니다(창이 시작 전 날짜를 포함하므로). 미래 누출이 아니라 기존 징후에 주입이 더해진 정상 동작입니다.

## 4-1. 하락 폭별 감지율 (최소 감지 하락)

**코호트 전체 결제가 줄어드는 경우의 감지율이며, 개인 고립이나 5% 이하의 작은 변화는 이 경보로 잡을 수 없다.**

4절과 **같은 쌍 목록**(840쌍, 같은 시작일·같은 대조)에 2·3·5·10·15·20% 계단형 하락을 14일 동안 넣었습니다(local 경로). 탐지율 = 0→1 / (0→0 + 0→1), 시작 전부터 경보 중인 쌍은 뺍니다. CI는 코호트(도시×연령×성) 단위 부트스트랩입니다(5,000번). 쌍은 서로 겹쳐 독립이 아니라서 쌍 단위로 재표집하면 범위가 지나치게 좁아집니다.

## 해석·평가의 남은 제한

- **분모**: 15% 계단형 탐지는 평가 가능 826쌍 · 대조 음성 817쌍 · 새 탐지 736쌍을 함께 적습니다. 90% = 736/817입니다. 순증 경보율 차이 +89%p는 같은 쌍의 확률 차이입니다.
- **무엇의 성능인가**: raw local 경보의 관측 후 활동 하락 감지 성능입니다. 공휴일·강수 반증 뒤 최종 후보의 탐지율이 아니고, 하락 시작 전 예측도 아닙니다. 등급 규칙(R-1)을 평가할 때는 raw와 검토 후 평가를 나눕니다.
- **주입 범위**: 4절은 코호트 하나만 낮춥니다. 도시 전체 하락은 4-2절의 작은 실험(도시당 시작일 20곳, 15% 계단형)으로만 봤습니다.
- **합성 오경보율**: AR(1) 10회 값은 그 생성 모형 조건의 값입니다. 실제 고립 오경보율·현장 정확도로 넓히지 않습니다.
- **같은 6개월로 설정·평가**: 임계값과 시작일을 같은 6개월에서 정하고 평가했습니다. 코드의 시간 누출 방지와 미래 기간 일반화는 다른 문제입니다. 임계값·모델을 고도화할 때는 시간 순서로 개발/검증 구간을 나눕니다.
- **7일 묶음**: 7일 안 재경보를 계속 이어 붙이므로 묶음은 7일보다 길 수 있습니다(이번 최대 27일). 반증은 첫 창만 봅니다.
- **사후 목록과 기준일 카드**: 경보_목록.csv는 사후 목록입니다. 경보 당일 상태는 경보_기준일카드.csv와 `records(panel, as_of=...)`로 봅니다.
- **카드 0건 가정**: 카드 `daily()`가 빠진 (날짜, 코호트)를 0건으로 채웁니다. 경보 모듈은 NaN을 미공급으로 다루지만, 지금 입력에서는 미공급과 거래 0을 구분할 수 없습니다.
- **공급 지연**: 관측일 t의 카드·도시 공통요인을 t에 쓸 수 있다고 가정한 재생입니다. 실제 공개일은 시간 계약(`contracts/time.py`)의 공급 가능일로 따로 다룹니다.
