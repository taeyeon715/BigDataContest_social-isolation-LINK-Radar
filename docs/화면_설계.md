# 화면 설계

LINK-Radar 대시보드(React)의 페이지 구성, 디자인 토큰, 시연 클릭 흐름입니다. 화면은 [API 명세](API_명세.md)만 부릅니다. 상태는 FastAPI만 씁니다([데이터 모델](데이터_모델.md)).

> **가짜와 실제가 섞여 있습니다.** 기본(`LINKRADAR_BACKEND=fake`)은 모든 응답이 가짜입니다. `LINKRADAR_BACKEND=real`이면 실행·질의응답·이어 묻기·스냅샷은 실제 그래프(`X-Data-Source: real`)이고, F3부터 현황·지도·후보 목록·자원 조회도 실제(발행된 정기 감시 실행, 원장 v2)입니다. 서버 설정에 따라 섞일 수 있어 화면은 전체를 한 번에 가짜라고 단정하지 않고, **페이지 제목 옆에 그 페이지가 부른 경로의 출처**를 작은 띠로 보입니다 (§1 출처 표시). "가짜 데이터" 띠가 보이는 부분은 분석 결과로 읽으면 안 됩니다.

## 0. 실행 방법

레포 맨 위 폴더에서 두 창을 엽니다.

```bash
# 1) API (http://localhost:8000)
uv sync
uv run uvicorn api.main:app --reload

# 2) 화면 (http://localhost:5173)
cd web
npm install
npm run dev
```

- 화면이 부르는 API 주소는 `web/.env`의 `VITE_API_BASE`로 바꿀 수 있습니다 (기본 `http://localhost:8000`).
- API는 화면 주소(`http://localhost:5173`, `http://127.0.0.1:5173`)만 허용합니다. 다른 주소는 `LINKRADAR_WEB_ORIGINS`(쉼표로 구분)로 지정합니다.
- 실행·검토·승인 기록은 `data/state/linkradar_fake.sqlite`에 남습니다 (`LINKRADAR_STATE_DB`로 바꿈). API를 껐다 켜도 승인 대기 실행이 그대로 이어집니다. 처음부터 다시 보려면 이 파일을 지웁니다.
- 가짜 실행이 끝나는 데 걸리는 시간은 `LINKRADAR_FAKE_DELAY`(초, 기본 1.5)입니다.
- 테스트: `uv run pytest -q tests/test_api.py`, `cd web && npm test`, `npm run build`

실제 그래프로 화면을 볼 때 (도구는 stub, LLM은 가짜 변형):

```bash
LINKRADAR_BACKEND=real LINKRADAR_TOOLS=stub LINKRADAR_LLM=fake \
LINKRADAR_STATE_DB=data/state/linkradar_try.sqlite \
uv run uvicorn api.main:app --port 8000 --workers 1
```

- 실제 그래프는 후보 ID로 조사를 열 때 **같은 기준일에 발행된 정기 감시 실행**에서 후보를 찾습니다. 먼저 `POST /runs`(`mode=monitoring`, 도시·기준일)로 정기 감시를 돌려 두어야 합니다.
- 후보 목록이 아직 가짜면 목록의 후보 ID와 정기 감시 후보 ID가 다를 수 있습니다. 이때는 후보 상세 주소(`/candidates/<정기 감시 후보 ID>`)로 바로 들어가 [조사 시작]을 누릅니다. 목록에 없는 후보도 [조사 시작]은 보입니다.

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 고지 | 모든 페이지 아래 검정 영역에 **"개인 판정 아님 · 최종 판단은 담당자"**. 지울 수 없음 |
| 시점 표시 | `analysis_mode=simulated_replay`인 응답에는 **"가정한 공개 시점"** 띠를 페이지 위에 붙임 (`time_label` 그대로) |
| 숫자 | 후보 수는 늘 범위와 함께 ("3건 · 임계값에 따라 2~5건") |
| 지도 | "위험지도"라고 부르지 않음. 구조 취약성 × 행동 신호 두 축을 따로 보임 |
| 색 | 빨강 경보 느낌을 피함. 등급은 차분한 파랑·청록 단계색, 판단 보류는 회색 줄무늬 |
| 문장 | 숫자·지역·방향이 든 문장은 Guard 사실 검사가 끝난 뒤에만 보임. 근거 표를 먼저, 설명 문장은 뒤에 |
| 상태 | 페이지마다 불러오는 중 / 비어 있음 / 오류 / 보류 네 상태를 따로 그림. 오류는 쉬운 문장을 제목으로, `error_code`는 작은 회색 글자로. **오류를 "0건·없음"으로 보이지 않음**: 카드마다 자기 오류와 [다시 시도]를 따로 보이고, 빈 상태 문장은 응답을 받았고 비어 있을 때만 |
| 느린·끊긴 API | 요청마다 60초 시간 제한(`TIMEOUT`)과 취소. 페이지를 떠나거나 도시·기준일을 바꾸면 진행 중 요청을 끊음. 도시·기준일을 바꾸면 새 응답이 올 때까지 옛 숫자를 보이지 않음. 불러오는 중이 3초를 넘으면 "처음 계산 중이라 10초 정도 걸릴 수 있습니다", 20초를 넘으면 [다시 시도]. 조사 상태 폴링은 잠깐 끊긴 오류(연결 실패·시간 초과·5xx)를 2·4·8·16초 간격으로 다시 시도하고("다시 묻는 중 n번째"), 그래도 안 되면 오류 상자 |
| 권한 | 서버에 "지금 누구" 경로가 없어 화면이 역할을 짐작함: `VITE_API_ROLE`이 있으면 그 값, 토큰이 없으면(개발 모드) 승인, 토큰만 있으면 공용 토큰 기본값인 조회. 403 `FORBIDDEN`을 받으면 한 단계 낮춰 잡음. 역할이 모자라면 버튼을 잠그고 "검토 권한이 필요합니다"(조사 시작·질의응답·이어 묻기·검토 저장·현장 결과·이의·정정 접수) / "승인 권한이 필요합니다"(승인·보류·추가 조사·이의·정정 처리) |
| 사람 이름 | 검토자·승인자는 서버가 기록한 이름을 그대로 보임(화면이 이름을 정하지 않음, 요청에는 `VITE_API_USER` 또는 "담당자(시연)"). `공용:<이름>`이면 옆에 "공용 계정" 표시 |
| 횟수 한도·예산 | 429 `RATE_LIMITED`는 "n초 뒤 다시 시도하세요"(`Retry-After`), `BUDGET_EXCEEDED`는 "AI 사용량을 다 써서 규칙·정해진 문장으로 대신 만듦" |
| 용어 | 낯선 말(과거 재생, 가정한 공개 시점, 공유 맥락, 해석 상태, 다른 원인 확인 등)에는 `?` 풀이를 붙임. 화면 글자만 쉬운 말로 바꾸고 데이터 값(`Level 2`, `부분 판정`, `반증`)은 그대로 둠. 해석 상태: 계산 재현 → "계산값", 가설 → "참고(확정 아님)". 부분 판정 → "근거 일부 빠짐". 반증 → "다른 원인 확인". 빠진 근거 코드(`weather_asos` 등)는 한국어 이름으로 |
| 접근성 | 글자 대비 4.5:1 이상(파란 상단 영역 그라데이션 끝도 흰 글자 5.2:1, 흰 반투명 글자 쓰지 않음), 글자 12px 이상, 키보드 포커스 테두리, 탭은 ←/→/Home/End. 확인창은 브라우저 `<dialog>`(뒤 화면 막힘, Tab은 창 안에서만, Esc로 닫고 연 버튼으로 포커스 복귀). 자원 판정은 라디오 묶음(Tab 한 번, ←/→로 고름), 메모 칸 이름은 "{자원 이름} 메모", 근거 확인 체크 이름은 근거 한 줄 해석. 지도 자원 표시와 그림에는 이름(`title`, `role="img"`) |
| 낱말 줄바꿈 | 본문 `word-break: keep-all`(한국어 낱말 중간에서 끊지 않음) |
| 거점 거리 | 서버 지표 "관측 거점까지 직선거리"는 화면에서 **"노인복지관·사회복지관(안부·관계 거점)까지 거리"**로 부르고, 한 번은 "행정복지센터(주민센터)는 안부·관계 프로그램을 운영하지 않아 이 거리에 넣지 않습니다. 직선거리이며 실제 이동 시간이 아닙니다"를 붙임. 같은 화면의 행정복지센터 자원에는 "행정 창구 · 거점 거리에 넣지 않음" |
| 출처 표시 | 응답 헤더 `X-Data-Source`를 경로 종류(현황·지도·후보 목록·자원·조사 실행·질의응답)별로 기억해, 페이지 제목 옆에 그 페이지가 부른 경로의 출처만 작은 띠로 보임. 모두 같으면 "실제 데이터" 또는 "가짜 데이터 · 화면 확인용, 분석 결과 아님" 하나, 섞이면 "후보 목록 가짜 데이터 · 조사 실행 실제 데이터"처럼 나눠서. `config`(설정 파일)는 표시하지 않음 |
| 오류 문장 | 새 오류 코드는 서버 문장보다 쉬운 문장을 먼저 보이고 서버 문장은 아래 작게: `CANDIDATE_NOT_IN_RUN`(이 조사의 후보만 고르세요), `RUN_NOT_READY`(조사가 아직 끝나지 않았습니다), `AGENT_ERROR`(조사 중 문제가 생겨 멈췄습니다 → 새 실행), `IDEMPOTENCY_KEY_REUSED`(같은 요청이 다른 내용으로 이미 들어옴 → 새로 고침), `RUN_NOT_AWAITING_APPROVAL`(이미 끝났거나 승인 대기가 아님), `EXTRA_ROUNDS_EXCEEDED`(추가 조사는 2번까지). 판 번호가 든 예전 코드(`REPORT_REVISION_STALE` 등)는 서버 문장 그대로 |
| 폭 | 노트북(1280px)과 태블릿(768px)에서 깨지지 않음. 좁으면 왼쪽 아이콘 바가 위쪽 가로 바로 바뀜. 휴대폰(390px)에서도 페이지 가로 스크롤 없음(그리드 열은 `minmax(0,1fr)`, 넓은 표는 그 안에서만 가로로 밀림) |

### 2.1 현황

**목적**: 오늘 무엇 때문에 무엇을 먼저 봐야 하는지 한눈에.

| 구성 | 내용 |
|---|---|
| 파란 상단 영역 | 기준일·도시 선택, 핵심 숫자 하나: "전체 n건" + "임계값에 따라 low~high건" + 종류별 수 |
| 오늘 먼저 볼 n건 | 상단 바로 아래. 검토 배정 순서대로 최대 3건 (지역·집단·등급·트리거). 누르면 상세 |
| 이번 주 트리거 카드 | 트리거 이름, 시작일, 규칙(R1·W 등). 없으면 "이번 주 트리거 없음" |
| 검정 알림 띠 | "추석 연휴 D-7 · 예정된 점검 n건" + 파란 둥근 버튼 [후보 검토하기] → 후보 목록(예정된 점검 탭) |
| 후보 수 그림 | 종류별 수와 범위 (CSS 막대 + 범위 선, 차트 라이브러리 없이. 첫 화면에서 Recharts를 받지 않음) |
| 이번 주 후속 확인 n건 | 검토 때 적은 후속 확인일이 기준일부터 7일 안이거나 지난 후보. 지난 것은 황토 "기한 지남". `GET /followups?city=&as_of=` 한 번으로 읽고 서버가 붙인 `state`(지남 / 이번 주 / 나중)를 씀 (실행마다 이력을 부르지 않음) |
| 현장 확인 결과 | `GET /outcomes/summary?city=&by=trigger` 한 번. 트리거별(예: "동절기(W)") 동·집단 수, 확인 가구·연락됨·부재·신규 연계·위기 발견 합계, 연락 비율. 합계가 10 미만인 칸은 숫자 없이 회색 "10 미만"(서버가 `null` + `small_cells`로 줌). 없으면 "아직 적은 현장 확인 결과가 없습니다" |
| 새로 생긴 / 해제된 후보 | "논현1동 · 중장년 남성 1인가구 · Level 2"처럼 지역·집단·등급 칩 (새 후보는 누르면 상세). 해제된 후보는 `released_candidates`의 지난 기준일 정보로 칩을 만들고 옆에 해제 사유(`release_reason`, 예: "트리거 기간이 끝남 (R4 폭염)")를 적음. 비교한 날(`compared_as_of`)을 오른쪽 위에. 옛 응답이면 ID만 |
| 출처·버전 (접힘, 맨 아래) | 스냅샷 ID만 늘 보이고, 펼치면 정제 규칙, 등급 규칙, 자원 원장 버전, 데이터 원천 이름 |
| 검정 하단 영역 | 스냅샷 ID, 데이터 기간, 고지 |

상태: 불러오는 중(회색 뼈대), 트리거·후보 없음("이 날은 확인할 트리거가 없습니다"), 오류(오류 코드 + 다시 시도). API가 꺼지면 상단 숫자 자리에 "후보 수를 불러오지 못했습니다 · 0건이라는 뜻이 아닙니다", 아래 카드(오늘 먼저 볼 후보·후속 확인·현장 확인 결과·바뀐 후보·후보 수)도 각자 오류 상자.

### 2.2 지도

**목적**: 어느 동이 구조적으로 취약하고, 거기에 지금 어떤 행동 신호가 걸려 있는지 두 축을 따로 보기.

| 구성 | 내용 |
|---|---|
| 지도 | 행정동 중심점에 원. **채우기 진하기 = 구조 취약성**(1인세대 비율 5단계), **테두리 모양 = 행동 신호**(예정된 점검: 굵은 청록 실선 / 이탈 경보(공유 맥락): 점선 / 없음: 테두리 없음). 자원은 작은 사각 표시, 전화형은 지도 밖 목록 |
| 범례 | "위험지도가 아닙니다. 두 축을 합친 점수가 없습니다." 공유 맥락 설명: "도시 단위 신호를 동에 같이 보여 준 것. 이 동의 결제가 줄었다는 뜻이 아님" |
| 산점도 (Recharts) | x = 구조 취약성, y = 노인복지관·사회복지관(안부·관계 거점)까지 직선거리(춘천) |

### 2.3 후보 목록

**목적**: 검토할 후보를 종류별로 나눠 보고, 이번에 배정된(K) 후보를 고르기.

| 구성 | 내용 |
|---|---|
| 흰 큰 패널 + 탭 | 예정된 점검 / 예상 밖 이탈 / 기각·보류 / 후속 확인 (기한 지난 수 배지, `GET /followups`의 `state`로 셈) |
| 필터 | 등급, 배정된 것만, 보기 방식(표 / 카드) |
| 표 보기 (기본) | 지역(상세 링크), 집단, 등급, 배정("1 / 3건"), 종류·트리거, 상태(다른 원인 확인·근거 일부 빠짐), 후속 확인일. 지역·등급·배정·후속 확인으로 정렬 |
| 카드 보기 | 가로로 넘기는 카드: 지역(동 또는 "도시 × 코호트"), 집단, 종류, 등급(이름까지), 근거 일부 빠짐 배지, 배정 표시, 트리거, 다른 원인 확인 결과, 후속 확인 배지 |
| 검토 예산 안내 | "검토 배정: 이번에 볼 수 있는 수 K건. 등급과는 따로 정합니다" |

탭 나누기: 기각(`counter_result=기각`)과 판단 보류(`candidate_level=판단 보류`)는 종류와 상관없이 "기각·보류" 탭으로 갑니다.

상태: 탭이 비면 "이 기준일에는 해당 후보가 없습니다".

### 2.4 후보 상세

**목적**: 근거를 확인하고, 자원을 고르고, 보고서를 승인·보류. 화면 순서는 담당자가 읽고 → 판단하고 → 결재하는 순서입니다: ① 요약 ② 근거 ③ 자원 판정 ④ 대응안·보고서 ⑤ 승인.

| 구성 | 내용 |
|---|---|
| ① 요약 | 등급 배지(이름까지), 종류, 근거 일부 빠짐, 배정, 실행 상태 한 줄. "왜 이 후보인가"(`level_reason`·트리거), **등급을 정한 조건**(`report.level_explanations`, 없으면 후보의 `rule_checks`: 조건마다 충족 / 미충족 / 자료 없음, 값·기준·기준까지 거리, "무엇이 바뀌면 등급이 바뀌나"), 다른 원인 확인 결과(이탈 후보), 할 수 있는 말 / 하면 안 되는 말, "지도에서 보기" |

[결과 저장] → `POST /runs/{id}/outcomes`(저장마다 새 멱등 키), 다시 적으면 [고쳐 저장]. 이 화면에서는 이 실행의 숫자를 10 미만도 그대로 보임 |
| 보고서 판 이력 | 판 번호, 만든 이유(처음 / 검토 변경 / 추가 조사), 시각 |
| 조사 상태 (맨 아래) | 한 줄("조사 완료 · 승인 대기 · 사실 검사 3종 통과"). [에이전트 경로 보기]를 누르면 지나온 노드, Guard 검사, 판단 기록(`decision_trace`: 단계 · 고른 것 · 누가(규칙/LLM/검사/템플릿) · 규칙 ID·이유). 실행 상태에 판단 기록이 없으면 보고서의 사본을 씀 |
| 인쇄용 보기 | 결재용 한 장(`@media print`): 근거 + 할 수 있는 말 + 등급 이유 + 핵심 사실 + 저장된 자원 판정 + 대응안·체크리스트 + 승인자·판·스냅샷·실행 ID + 대외용 문구 + 고지. 위에 "내부용(대외비)". **장마다** `@page` 여백 상자로 오른쪽 위 "내부용(대외비)", 오른쪽 아래 "내부용(대외비) · 쪽/전체", 왼쪽 아래 "개인 판정 아님"(Chromium 131+, PDF로 확인). 근거는 ID 대신 "근거 1·2·3" 번호, 문장 속 `[EV-…]`는 "(근거 n)", 자원 코드는 이름. 근거 번호와 기록 ID 대응은 맨 아래 작은 글자 한 줄. 승인자는 서버 기록 그대로(공용 계정이면 그 표시). 상세 화면에서 Ctrl+P를 눌러도 이 한 장만 인쇄됨. PDF는 브라우저 인쇄의 "PDF로 저장" |

상태: 판단 보류 후보는 요약에 회색 안내 "판단 보류: 빠진 근거 — 기상 관측 날씨 (ASOS)" (`weather_asos`를 한국어 이름으로). 승인 거절(409)은 그 사유 문장을 보임(새 코드는 §1 오류 문장). 검토 저장은 지금 근거 카드에 있는 근거 ID만 보냄(추가 조사로 빠진 근거는 빼서 `EVIDENCE_NOT_IN_RUN`을 막음).

### 2.5 질의응답

**목적**: 짧은 질문에 근거로 답하고, 답할 수 없으면 왜 못 하는지와 필요한 자료를 보이기.

| 구성 | 내용 |
|---|---|
| 질문 입력 | 예시 질문 버튼 3개 (D4 "강남 60대의 밤 활동은 어때?" 포함) |
| 진행 표시 | "근거 모으는 중 → 사실 검사 중". 이 동안 답 문장은 보이지 않음 |
| 근거 표 | 먼저 보임 |
| 설명 문장 | 근거 표 다음에 보임. 문장 안 `[EV-…]`는 근거 표 행으로 이동 |
| Guard 판정 | 신호 / 사실 / 표현 따로 |
| 보류 답변 | "답할 수 없는 질문입니다" + 쉬운 문장 + 필요한 자료 목록. 사유 코드는 작은 회색 글자로 |

### 2.6 실행 기록

**목적**: 어떤 실행이 어떤 스냅샷·규칙·원장 버전으로 돌았고, 누가 무엇을 승인했는지.

| 구성 | 내용 |
|---|---|
| 실행 표 | 실행 ID, 모드, 상태, 기준일, 스냅샷, 정제·등급 규칙, 자원 원장, 보고서 판, 만든 시각 |
| 펼치기 | 보고서 판 이력, 검토 기록(자원 판정, 후속 확인일), 승인 기록(결정, 판, 승인자, 멱등 키) |

## 5. 시연 클릭 흐름 (D1~D4)

가짜 API의 값은 아래 흐름이 클릭만으로 재현되도록 맞춰 두었습니다.

### D1. 강남 구조 취약성 검토

1. 현황에서 도시 **강남**, 기준일 **2025-09-26** → 트리거 "추석 연휴 D-7", 검정 띠 "예정된 점검 n건"
2. [후보 검토하기] → 후보 목록 "예정된 점검" 탭 → 카드 **논현1동 · 중장년 남성 1인가구 · Level 2 · 배정 1**
3. 카드 → 후보 상세 → [조사 시작] → 상태 진행 후 "승인 대기"
4. 근거 표: 1인세대 비율(주민등록, 행정동 × 월), 시민생활 "소통 적음" 남녀 비(강남 전체 · 탐색적 · 해석 상태 가설), 트리거
5. 지도에서 강남 1인세대 상위 동(진한 원)과 예정된 점검 테두리를 같이 확인

### D2. 춘천 읍·면 동절기 점검

1. 현황에서 도시 **춘천**, 기준일 **2025-11-14** → 트리거 "동절기 (춘천 읍·면)"
2. 지도 → 면 지역 원이 테두리(예정된 점검), 표에서 북산면·남면의 안부·관계 거점(노인복지관·사회복지관)까지 직선거리. 남면을 고르면 "거점 18.3km"와 "남면 행정복지센터 0.2km (행정 창구 · 거점 거리에 넣지 않음)"가 같이 보임
3. 후보 목록 → **북산면 · 고령층 · Level 3** → 상세: 접근성 근거(직선거리), 전화형 자원(외로움안녕120), "위치 확인 필요" 자원
4. 자원 판정: 외로움안녕120 **적합**, 노인복지관 **보류**(메모) → [검토 저장] → 보고서 "다시 만드는 중", 승인 버튼 잠김 → 잠시 뒤 새 판 → [승인]

### D3. 달력 효과로 경보 기각

1. 도시 **강남**, 기준일 **2025-10-13** → 후보 목록 "기각·보류" 탭
2. 카드 **강남 · 40대·50대 남성 · 예상 밖 이탈 · 기각 · Level 1** → 상세
3. 반증 결과 "기각: 추석 연휴 감소가 공휴일 기대값으로 설명됨(R5)". 근거 표에 공휴일 기대값 대비 비율
4. "예상 밖 이탈" 탭의 **강남 70대·80대+ · 도시 공통 변화 / 확인 필요 · Level 1** 카드와 비교 (평소 수준으로 안 돌아왔지만 도시 전체도 낮음). "기각·보류" 탭의 **강남 60대 · 검토 중 · 판단 보류**(회복 판정 기간 전)도 함께 봄

### D4. 근거 부족 보류

1. 질의응답 → 예시 버튼 **"강남 60대의 밤 활동은 어때?"**
2. "답할 수 없는 질문입니다": `GRAIN_FORBIDDEN_COMBO` + 필요한 자료(연령 × 시간대 통신 자료, 또는 카드 데이터1 60대 18~23시 결제)
3. 비교: "강남 1인세대 비율 상위 동은?" → 근거 표가 먼저, 설명 문장이 뒤에
4. 후보 쪽 보류 예: 춘천 기준일 2025-09-26 "기각·보류" 탭 → **춘천 · 80대+ · 판단 보류**(빠진 근거 weather_asos)

## 6. 가짜 API에서 명세와 다른 점

| 항목 | 가짜 API | 이유 |
|---|---|---|
| `GET /runs` (`candidate_id`, `limit`) | 실행 목록 + 스냅샷·규칙·원장 버전 | 실행 기록 페이지와 "이 후보로 만든 실행" 찾기에 필요. 명세에 없음 |
| `GET /runs/{id}/report` | 지금 판의 `Report` | 보고서 문장을 줄 경로가 명세에 없음 |
| `GET /runs/{id}/history` | 보고서 판·검토·승인 기록 | 보고서 판 이력, 승인 기록 화면용 |
| `409 RUN_NOT_READY` | 실행이 끝나기 전에 근거·보고서를 부르면 | 명세 오류 표에 없음 |
| 보고서 다시 만들기 | 검토 저장 뒤 `LINKRADAR_FAKE_DELAY`초 지나면 자동으로 새 판 | 진짜는 그래프의 `write_report`·`guard_report`가 함 |
| 반증 "검토 중", "확인 필요" | `counter_result=보류` + `counter_reason`이 "검토 중:", "도시 공통 변화 / 확인 필요:"로 시작 | `CounterResult`에 두 값이 없음 |
| 지도 좌표 | 화면이 `centroids.ts`로 붙임 | `MapArea`에 좌표가 없음 |
| 실행 결과 저장 | SQLite `run_results` 표(가짜 전용) | 진짜는 LangGraph 체크포인트 |

실제 그래프(`LINKRADAR_BACKEND=real`)에 맞춘 계약: 발행 판 `published_report_revision`, 추가 조사 `focus`·`extra_rounds`, 보고서 `round_changes`·`review_ids`, 실행 자원 `GET /runs/{id}/resources`(자원당 한 줄, `candidate_ids`), 이어 묻기 `POST /runs/{id}/followup`, 새 오류 코드, 해제 사유 `released_candidates`, 후속 확인 `GET /followups`, 조사 시작 `city`·`monitoring_run_id`, 자원 조회 `limit`·`total`. 타입은 `web/src/api/types.ts`, 명세 예시를 옮긴 시험 자료는 `web/src/test/fixtures.ts`.
