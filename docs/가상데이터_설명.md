# 가상 데이터 설명

대회 규정(주제설명자료 p.10 "데이터 활용 규칙")은 가상 데이터(synthetic data)를 쓰면 **생성 방식 설명자료**를 내라고 합니다. 이 문서가 그 설명자료입니다.

LINK-Radar는 가상 데이터를 네 가지로 씁니다. 모두 **규칙과 코드가 설계대로 도는지 확인하는 용도**이고, 실제 사회적 고립을 찾았다는 근거로 쓰지 않습니다.

| # | 종류 | 무엇을 만드나 | 쓰는 곳 | 코드 |
|---|---|---|---|---|
| 1 | 하락 주입 실험 | 실제 카드 시계열의 한 집단(또는 도시 전체)에 일부러 하락을 넣음 | 경보 성능 평가 (EDA-6, M1, R-1) | `notebooks/eda6_alarm_reeval.py`, `src/bigcontest/models/evaluate.py` |
| 2 | 정상 합성 시계열 | 실제 자료의 요일 효과·흔들림만 빌린, 이상이 없는 시계열 | 오경보율 계산 | `src/bigcontest/signals/alarm.py` `synthetic_normal` |
| 3 | 페르소나 주입 | "이런 집단에 이런 변화가 생기면" 5가지 장면 | 등급 규칙 검증 (R-1) | `notebooks/r1_level_rules.py` `persona()` |
| 4 | 화면·도구 개발용 가짜 값 | 지어낸 후보·등급·자원, 고정 결과 도구, 가짜 LLM | 화면 개발, 그래프 분기 시험 | `api/services/fake_data.py`, `src/bigcontest/agent/tools/stubs.py`, `src/bigcontest/agent/llm.py` `FakeLLM` |

공통 원칙
- 원천 데이터를 새로 지어내지 않습니다. 1~3은 **실제 카드 집계에 정해진 비율을 곱한 것**이고, 원본 파일은 바꾸지 않습니다(메모리 안에서만 바꿈).
- 가상 데이터로 낸 숫자는 리포트와 문서에 **"합성"**으로 표시합니다. 실제 자료 결과와 같은 숫자로 발표하지 않습니다.
- 4는 분석 결과가 아닙니다. 화면에는 "가짜 데이터" 띠가, API 응답에는 `X-Data-Source: fake`가, 가짜 도구 결과에는 `data_version="stub"`이 붙습니다.

## 1. 하락 주입 실험 (EDA-6, M1)

### 왜 필요한가
고립의 정답 자료가 없어서 "경보가 진짜 고립을 잡았나"를 잴 수 없습니다. 대신 **크기와 시점을 아는 하락**을 일부러 넣고, 경보가 그것을 얼마나 빨리 잡는지 봅니다.

### 만드는 방법
- 자료: 카드 데이터2, 도시 × 연령(20대~80대+) × 성 = **코호트 28개**, 184일(2025-07-01~12-31).
- **쌍 목록을 한 번만 뽑아 고정**: 코호트마다 시작일 30곳 → **840쌍**(난수 시드 0). 시작일은 학습 기간(28일)과 첫 판정 창 뒤, 주입 14일과 그 앞뒤 하루에 공휴일이 끼지 않는 날에서 고릅니다.
- 같은 쌍에 **대조(주입 없음)**와 **주입**을 모두 돌려 비교합니다(짝지은 실험). 대조에서 이미 울린 쌍은 탐지로 세지 않습니다.
- 주입 모양

| 실험 | 주입 | 쌍 수 | 리포트 |
|---|---|---|---|
| 계단형 | 시작일부터 14일 동안 결제건수 × (1 − 하락률), 하락률 10·15·20% | 840 | [EDA-6 4절](../reports/eda6_사전경보재평가/README.md) |
| 하락 폭별 | 같은 쌍에 2·3·5·10·15·20% | 840 | EDA-6 4-1절 |
| 점진형 | 14일에 걸쳐 0 → 15% 선형 | 840 | EDA-6 4절 |
| 도시 전체 | 그 도시 14개 코호트를 모두 14일 동안 15% (도시마다 시작일 20곳, 시드 1) | 도시당 20 | EDA-6 4-2절 |
| 모델 잔차로 다시 | 같은 840쌍 중 모든 모델이 판정할 수 있는 시작일 ≥ 09/14 | 601 | [M1 3절](../reports/m1_기대활동모델/README.md) |
| 지속 조건 비교 | 코호트마다 14일 15% 감소 | 504회 | [R-1 4-2절](../reports/r1_등급규칙/README.md) |

- 경보는 과거 자료만 씁니다. 주입한 날이 쌓이면 뒤쪽 기준값도 같이 내려갑니다(실제 운영과 같음).
- 신뢰구간은 **코호트 단위 부트스트랩**(5,000번)입니다. 같은 코호트의 시작일 30곳은 기간이 겹쳐 독립이 아니기 때문입니다.

### 결과 (합성)

| 항목 | 값 |
|---|---|
| 15% 계단형, 코호트 전체 하락 | 736 / 817 = **90%** (코호트 단위 CI 81~98%), 지연 중앙값 2일 |
| 하락 폭별 | 2% → 2%, 3% → 9%, 5% → 32%, 10% → 77%, 20% → 95% |
| 도시별 15% | 강남 98%, 춘천 82%, 춘천 80대+ 17% |
| 점진형 15% | 628 / 817 = 77%, 지연 중앙값 8일 |
| 도시 전체 15% | 도시 경보 강남·춘천 100%, 코호트 local 경로 0% (설계상 울리지 않아야 함) |

### 보여 주는 것 / 보여 주지 못하는 것
- 보여 주는 것: **코호트 전체**(예: "춘천 가맹점의 강원 거주 80대+ 여성 고객 전체") 결제가 정해진 만큼 줄면 경보가 얼마나 빨리, 얼마나 자주 울리는가.
- 보여 주지 못하는 것
  - 실제 고립 탐지율. 개인 몇 명이 고립되어도 코호트 전체 결제는 거의 움직이지 않습니다. 2% 하락 감지율이 2%라는 것이 그 뜻입니다.
  - 반증(공휴일·강수) 뒤 최종 후보의 성능. 위 값은 반증 전 raw 경보입니다.
  - 미래 기간 성능. 임계값과 평가를 같은 6개월에서 했습니다.
  - 실제 하락 모양. 14일 계단형은 쉬운 과제입니다. 실제 변화는 더 느리거나 일부 업종에만 생길 수 있습니다.

## 2. 정상 합성 시계열 (오경보율)

### 만드는 방법 (`synthetic_normal`)
- log(결제 + 1) = 코호트 요일 평균 + 도시 공통 잡음 + 코호트 잡음. 두 잡음은 AR(1)입니다.
- 실제 자료에서 빌리는 것: 수준, 요일 효과, 흔들림 크기(MAD), 이웃한 날 자기상관(실제 중앙값 0.27 → 합성 0.28로 맞춤).
- 넣지 않는 것: 공휴일 효과, 추세 변화, 이상. 그래서 여기서 울린 경보는 정의상 모두 오경보입니다.
- 시드 0~9로 10개를 만들어 같은 경보 규칙을 돌립니다.

### 결과 (합성 조건)
- 평가창당 오경보 1.6%, 코호트·일당 0.47% (EDA-6 5절).
- 실제 자료에서 아무것도 넣지 않았을 때 울린 비율(배경 경보율 2.4%, 코호트·일당 2.8%)과는 **다른 숫자**입니다. 배경 경보율은 그 기간이 정말 정상이었는지 몰라 오경보율이라고 부르지 않습니다.

### 보여 주지 못하는 것
- 실제 자료의 오경보율, 현장에서의 헛걸음 비율. 생성 모형(AR(1) 잡음) 조건의 값일 뿐입니다.

## 3. 페르소나 주입 (R-1, 등급 규칙 검증)

### 만드는 방법
- 카드 패널의 **한 코호트**에 지정한 기간 동안 결제를 20% 줄인 패널을 메모리 안에 만들고, 실제 등급 규칙(rules-v1.0, 비교안 D)을 그대로 돌립니다.
- 페르소나는 개인이 아니라 **"이런 집단 변화 장면"**입니다. 이름·나이·주소 같은 개인 속성은 만들지 않습니다.

| 페르소나 | 주입 | 기준일 | 기대 | 결과 |
|---|---|---|---|---|
| P1 평소 기간 지속 하락 | 춘천 70대 여성 11/03~11/30 20% 감소 | 11/12 | 반증 통과 → Level 2 | 맞음 |
| P2 연휴 중 평소보다 더 깊은 하락 | 춘천 70대 남성 10/03~10/13 20% 감소 | 10/24 | 기각되지 않음 | 맞음 (Level 2) |
| P3 연휴 뒤에도 지속 | 춘천 70대 여성 10/03~11/09 20% 감소 | 10/24 | 기각되지 않음 | 맞음 (판단 보류) |
| P4 겨울 고령 지속 하락 | 춘천 80대+ 남성 12/01~12/31 20% 감소 | 12/12 | 이탈 Level 2, 같은 날 동절기 점검은 부분 판정 | 맞음 |
| P5 작은 코호트 하락 | 춘천 80대+ 여성 11/03~11/30 20% 감소 | 11/12 | 못 잡을 수 있음 (한계 확인용) | 후보 없음 (예상대로) |

- 기대와 맞은 페르소나 **5/5**. P5는 "결제가 적은 80대+ 집단은 카드 신호로 잡기 어렵다"는 한계를 일부러 보여 주는 장면입니다.

### 보여 주는 것 / 보여 주지 못하는 것
- 보여 주는 것: 규칙이 설계한 대로 연휴 감소는 걸러 내고(P2·P3), 평소 기간 하락은 올리고(P1·P4), 작은 집단은 놓칠 수 있음(P5)을 숨기지 않는다.
- 보여 주지 못하는 것: 실제 고립을 찾는 비율, 순위가 옳은지. 카드는 도시 단위라 "먼저 확인할 동"은 그 도시 1인세대 비율 상위 동으로만 나옵니다.

## 4. 화면·도구 개발용 가짜 값

| 무엇 | 어디 | 어떻게 표시하나 | 쓰는 이유 |
|---|---|---|---|
| 가짜 API 응답 | `api/services/fake_data.py` (`LINKRADAR_BACKEND=fake`, 기본값) | 응답 머리 `X-Data-Source: fake`, 화면 출처 띠 "가짜 데이터", 인쇄용 보기에 "분석 결과 아님" | 실제 분석이 끝나기 전에 화면 흐름(D1~D4)을 클릭으로 확인 |
| 가짜 도구 | `src/bigcontest/agent/tools/stubs.py` (시나리오 17개) | `data_version="stub"`, 경고 "가짜 도구(stub) 고정값: 실제 분석 결과 아님" | 그래프의 모든 분기(보류·기각·시간 초과·관할 밖 자원 등)를 테스트로 밟기 |
| 가짜 LLM | `src/bigcontest/agent/llm.py` `FakeLLM` (변형 여러 개) | `model_id="fake"` | "LLM이 무엇을 골라도 등급이 같다", "틀린 사실을 Guard가 잡는다"를 네트워크 없이 시험 |

- 가짜 API의 행정동 이름·중심점만 실제 코드표(`ref/adm_cd_names.csv`)에서 읽고, 1인세대 비율·후보·등급·자원은 **지어낸 값**입니다.
- README의 대시보드 캡처는 가짜 데이터 화면이 아니라 **실제 백엔드**(`LINKRADAR_BACKEND=real`, 실제 데이터) 화면입니다. 가짜 API 화면에는 출처 띠 "가짜 데이터"가 붙어 구분됩니다.
- 이 값들은 어떤 리포트 숫자에도 들어가지 않습니다.

## 5. 한눈에

|---|---|---|---|
| 하락 주입 | 코호트 전체가 X% 줄면 몇 %를 며칠 만에 잡나 | 실제 고립을 몇 % 잡나 | 합성 검증 |
| 정상 합성 시계열 | 이상이 없을 때 규칙이 얼마나 헛울리나 | 실제 자료의 헛경보율 | 합성 조건 |

| 가짜 API·도구·LLM | 화면과 그래프가 모든 분기에서 도나 | 분석 결과 전부 | 분석 아님 |

```bash

uv run python notebooks/r1_level_rules.py       # 페르소나 5개
```
