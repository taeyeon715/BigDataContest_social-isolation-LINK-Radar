# LLM 활용 설명

대회 규정에 따라 LINK-Radar에서 생성형 AI(LLM)를 **어디에, 어떻게, 어디까지** 쓰는지 정리한 문서입니다. 코드 기준은 `src/bigcontest/agent/llm.py`, 설정은 `configs/llm.yaml`, 프롬프트는 `configs/prompts/`입니다.

## 1. 한 줄 원칙

**판단은 코드, 설명은 LLM.** 후보·등급·근거 숫자는 Python 코드와 규칙 파일(`configs/*.yaml`)이 정합니다. LLM은 담당자의 질문을 해석하고, **근거를 본 뒤 무엇을 더 확인할지 고르고**(조사 루프), 근거를 쉬운 문장으로 풀어 쓰는 일만 합니다. LLM이 꺼져 있어도 같은 등급과 보고서(템플릿 문장)가 나옵니다.

## 2. 사용 모델

| 용도 | 모델 | 이유 |
|---|---|---|
| 질문 해석, 추가 조사 선택, 설명 문장 | Claude Sonnet 5.5 (`claude-sonnet-5-5`) | 한국어 이해, 구조화 출력(JSON 스키마) 안정성 |
| 정기 감시 대량 브리핑 | Claude Haiku 5.5 (`claude-haiku-5-5`) | 짧은 요약을 많이 만들 때 비용이 낮음 |
| 정적 배포본(Vercel) 첫 화면 질문창 | Gemini 2.5 Flash-Lite (`gemini-2.5-flash-lite`), 무료 등급 | 결제수단 없는 키로 무료 한도 안에서만 씀. 시험 호출 응답 약 2초 |

- 모델 ID와 가격은 `configs/llm.yaml` 한 곳에만 둡니다(가격: Anthropic 공식 가격표, 2026-10-13 확인).
- 출력은 모두 **JSON 스키마 구조화 출력**으로 받고 Pydantic으로 다시 검사합니다. 형식이 틀리면 1회 다시 묻고, 그래도 실패하면 규칙 기반·템플릿으로 대신합니다.

## 3. LLM이 하는 일 (여덟 자리)

| 자리 | 입력 | 출력 | LLM이 없을 때 | 프롬프트 |
|---|---|---|---|---|
| 질문 해석 (`classify`) | 담당자 질문 (개인정보 가린 뒤) | 경로(조회/조사/범위 밖), 정규화한 요청(도시·동·집단·기간·지표. 동·기간은 규칙이 비운 칸만) | 규칙 기반 분류 | `classify_v3` |
| 추가 조사 선택 (`choose_extra_tools`) | 정규화한 요청, 쓸 수 있는 도구 목록 | 추가로 부를 도구 이름 (허용 목록 5개 안에서만: 도구 21개 중 나머지는 그래프가 정해진 순서로 부름) | 추가 조사 없음 | `choose_tools_v1` |
| 조사 루프 질문 고르기 (`investigate`) | 반증 뒤 코드가 고정 목록에서 만든 미해결 질문(최대 8개)·후보 요약·이미 확인한 것 | 확인할 질문 key 많아야 3개(enum) + 질문마다 이유. 코드가 정해진 도구를 실행하고 결과는 보고서 "추가로 확인한 것"에만 | 우선순위 규칙으로 고름 | `investigate_v1` |
| 설명 문장 (`explain`) | 근거 카드 요약 (근거 ID·지표·방향) | 쉬운 설명 문장 2~4개, 근거 ID 인용 | 템플릿 문장만 | `explain_v4` |
| 정기 감시 브리핑 (`brief`) | 후보 목록 요약 | 짧은 브리핑 문장 | 템플릿 문장만 | `brief_v3` |
| 추가 조사 계획 (`plan_more`) | 담당자가 고른 범위와 메모 (개인정보 가린 뒤) | 도구·반증 계획 (허용 목록 안에서만) | 메모 낱말 규칙 | `plan_more_v1` |
| 이어 묻기 종류 (`followup_intent`) | 개인정보 가린 질문 (규칙 낱말로 종류를 못 정할 때만) | 등급 이유 / 자원·대응 / 비교 / 자료 한계 / 기타 (enum) | 기타 | `followup_intent_v1` |
| 이어 묻기 (`followup`) | 보고서 근거 카드, 질문 종류, 이미 답에 든 템플릿 문장 | 근거 ID만 인용하는 보충 설명 문장 | 템플릿 문장만 | `followup_v3` |

조사 루프(`investigate`)는 에이전트가 **근거를 본 뒤 판단하는 자리**입니다. 반증까지 끝난 후보를 보고 "연휴 회복 미확인", "날씨로 설명되는 부분", "연휴 중 의료 접근" 같은 질문 중 무엇을 먼저 확인할지 고르고 이유를 씁니다. 코드가 그 질문의 도구를 돌려 풀림·여전히 모름을 정하고, 못 푼 질문이 있으면 한 회차 더 봅니다(최대 2회차). 질문 목록·도구·한도는 코드가 정하고 LLM은 고르기만 합니다([에이전트 설계 §4.1](에이전트_설계.md#41-조사-루프-관찰--계획--실행--확인-agentinvestigationpy)).

## 4. LLM이 하지 않는 일

- **등급·후보를 정하지 않습니다.** 필수 근거 도구는 LLM이 고르지 않아도 항상 실행되고, 등급은 규칙이 계산합니다. 조사 루프 결과도 등급·순서·반증 입력에 넣지 않습니다(따로 둔 `investigation_evidence`). 가짜 LLM 7종 × 시나리오 7개와 녹화한 실제 Claude 응답 재생에서 등급·순서·반증이 LLM 없음과 같다는 테스트가 있습니다(`tests/test_determinism.py`, `tests/test_llm_replay.py`, `tests/test_demo_cases.py`).
- **숫자를 만들지 않습니다.** 보고서의 숫자·사실 문장은 근거 카드에서 템플릿으로 넣습니다. LLM 설명 문장에 숫자(한글 수량 포함)나 근거에 없는 사실이 들어가면 Guard가 수정(REVISE)을 요구하고, 두 번 넘게 반복되면 보류합니다.
- **개인을 찾거나 판정하지 않습니다.** 개인을 지목하는 질문은 LLM에 보내기 전에 코드가 범위 밖으로 처리합니다.
- **원천 데이터를 보지 않습니다.** LLM에는 집계된 근거 카드 요약만 들어가고, 카드·통신 원자료와 자원 원장 원문은 들어가지 않습니다.
- **경로를 함부로 바꾸지 않습니다.** 규칙이 정한 조사 경로를 LLM이 낮출 수 없습니다.

## 5. 안전장치

| 장치 | 내용 |
|---|---|
| 계약 검사 | 데이터에 없는 조합(예: 연령 × 시간대), 기준일 뒤 자료는 LLM 호출 전에 코드가 보류 |
| 개인정보 가리기 | 질문·메모를 저장하기 전, 그리고 LLM에 보내기 전 전화번호·주민번호·이메일·상세 주소(번지·호·도로명+번호)·사람 이름(호칭·`에게`/`한테`/`께`가 붙은 이름, 조사 뒤에 연락·방문·확인이 오는 이름, 영문 이름 등. `agent/pii.py`)을 가림. 가린 개수만 기록. 이름이 든 질문은 LLM에 보내지 않고 개인 지목으로 보류 |
| 보고서 Guard | 사실 검사(지표·지역·기간·값·단위·방향·근거 ID 대조)와 표현 검사(거주민 단정, 진단 문장, 정확도 주장, 지표를 다른 뜻으로 바꾸기) |
| 적대 테스트 | 개인 지목·주입 문구 질문, 방향 바꾸기·한글 수량·반어 부정 문장을 묶은 테스트 세트 |
| 재시도 한도 | Guard 수정 요구 최대 2회, 넘으면 판단 보류. 신호 Guard는 규칙별 처치(근거 빼기·실패한 도구만 다시·바로 보류)로, 전체를 다시 모으지 않음 |
| LLM 이유 검사 | 조사 루프에서 LLM이 쓴 "고른 이유"도 숫자·진단 말이 있으면 보고서에 싣지 않음(Guard 표현 검사) |

## 6. 비용과 기록

- 호출마다 모델 ID, 프롬프트 버전, 입력·출력 토큰, 소요 시간, 비용(USD)을 LLM 호출 기록(`llm_calls`)에 남깁니다. 이 기록에는 API 키와 질문·메모가 없습니다.
- 질문·검토 메모·승인 메모 자체는 실행 기록(`runs`·`reviews`·`approvals`)에 남지만, **저장하기 전에 개인정보를 가린 글**만 남깁니다(전화번호·주민번호·이메일·상세 주소·사람 이름 → `[전화번호]`·`[이름]` 등). 그래프 체크포인트에도 가린 질문만 들어갑니다. 자동 가리기는 개인정보를 줄일 뿐 모두 지운다고 보장하지 못합니다(규칙 기반이라 별명·이름만 쓴 말·드문 표기는 빠질 수 있음). 자유 글에는 개인정보를 쓰지 않는 것이 원칙입니다. 가린 글도 보존 기한(기본 365일, `LINKRADAR_TEXT_RETENTION_DAYS`)이 지나면 `uv run python -m api.retention --db <상태 DB>`로 비웁니다.
- **실행당 예산**: `configs/llm.yaml`의 `budget`(실행 하나에 호출 40번, $1.0). 그래프·검토 반영·추가 조사·이어 묻기가 같은 예산을 나눠 쓰고, 넘으면 LLM을 부르지 않고 규칙·템플릿으로 대신합니다(`llm_calls.error_code = BUDGET_EXCEEDED`). LLM을 부르는 요청(실행·질의응답·이어 묻기)은 검토 역할 이상이고 사용자마다 횟수 한도가 있습니다([API 명세](API_명세.md) §1).
- **도구 시간 예산**: 같은 `budget`의 `max_tool_ms_per_run`(300초). 넘으면 조사 루프를 멈추고 이유를 보고서에 남깁니다. 도구마다 제한 시간(`tools.timeout_s`, 기본 20초)을 넘으면 `TOOL_TIMEOUT`.
- 조사 1회: Claude 호출 4~6번(질문 해석 1·도구 선택 1·조사 고르기 1~2·설명 1, Guard가 다시 쓰라고 하면 설명 +1), 약 $0.03~0.06. 실측은 실제 데이터 시연(2026-10-14, `llm_calls`) 4번 $0.033~0.034·LLM 응답 시간 합 13~19초, 녹화 묶음(§7)의 조사 1개 5번(조사 고르기 2회차) $0.035입니다. 에이전트 연결 시험 전체는 18회, 약 $0.15였습니다.
- 시연 사례 한 번(조사 1 + 추가 조사 1 + 검토 반영 1 + 이어 묻기 2 + 질의응답 2): Claude 호출 13번, 약 $0.12 (실제 데이터 시연 `llm_calls` 합계 $0.115). 정기 감시는 LLM 없이 규칙만이라 비용이 없습니다.
- 녹화 묶음(아래 §7) 실측: 조사 1개 + 조회 1개 + 이어 묻기 3개 = Claude 호출 11번, 입력 30,030·출력 2,477 토큰, $0.085 (Sonnet 5.5 공식 가격).
- 실제 API를 부르는 테스트는 `RUN_LLM_TESTS=1`일 때만 돌고, 평소 테스트는 네트워크를 쓰지 않습니다.

## 7. 품질 평가 (녹화·재생, 골든 질문)

"LLM 설명이 좋아졌다/나빠졌다"를 숫자로 말하려고 작은 평가 묶음을 둡니다. 기본 테스트는 유료 API를 부르지 않습니다.

| 묶음 | 내용 | 파일 |
|---|---|---|
| 골든 질문 20개 | 질문 → 기대 경로·대상(도시·동·집단)·끝점. 조사 8, 조회 6, 보류 6("춘천 강남동", "역삼동" 되묻기, 개인 지목 등) | `tests/eval/golden.yaml` |
| 이어 묻기 골든 15개 | 종류 5가지 × 3. 기대 종류와 상태(답함 / `NO_TARGET` / `NO_DATA`), 자원 답에 자원 이름 | 같은 파일 `followups` |
| 녹화·재생 | 실제 Claude 응답을 한 번 녹화(`scripts/llm_cassette.py record`)해 `tests/fixtures/llm_cassettes/smoke_v1.json`에 두고, 테스트는 `llm="replay:…"`로 재생. 열쇠는 모델+프롬프트+입력의 해시라 프롬프트·입력이 바뀌면 "녹화에 없음"으로 드러남. 녹화본에는 키·질문 원문이 없음 | `agent/cassette.py`, `tests/test_llm_replay.py` |
| 지표 표 | `uv run python scripts/eval_agent.py` | `agent/evaluation.py` |

설명 지표 (코드로 계산)

- **인용률**: LLM 설명 문장 중 근거 ID를 하나 이상 인용한 비율
- **1회 Guard 통과율**: 첫 보고서가 사실·표현 검사를 한 번에 지난 비율
- **대상 충실도**: 후보 ID(없으면 동 이름)를 말한 설명 문장이 인용한 근거가 그 후보·그 동의 근거이거나 동 없는 도시 근거인 비율
- **Guard 전 제거율**: LLM이 쓴 설명 문장 중 Guard 전에 뺀 비율. 뺀 이유는 코드로 남김(숫자·수량 말·방향·도시·동·근거 ID·후보 주장)

실측 (가짜 도구, 2026-10-14)

| 지표 | LLM 없음 | 가짜 LLM | Claude (녹화 재생) |
|---|---|---|---|
| 경로 정확도 (골든 20) | 100% | 100% | — |
| 대상 정확도 | 100% | 100% | — |
| 끝점 정확도 | 100% | 100% | — |
| 이어 묻기 종류 정확도 (15) | 100% | 100% | — |
| 이어 묻기 상태 정확도 | 100% | 100% | — |
| 설명 문장 수 | 0 | 28 | 5 |
| 인용률 | — | 0% | 60% |
| 1회 Guard 통과율 | 100% | 100% | 100% |
| 대상 충실도 | — | — | 100% |
| Guard 전 제거율 | — | — | 38% (후보 주장 1, 방향 1) |

- Claude 열은 녹화 묶음(조사 1·조회 1)만이라 표본이 작습니다. 골든 질문 전체를 녹화하면 비용이 커서(약 $1) 프롬프트 판을 올릴 때만 하고, 평소에는 재생합니다.
- 경로를 뒤집는 가짜 LLM(`fake_flip_route`)은 경로 정확도 65%로 나옵니다(조회 질문을 조사로 올림, 낮추기는 막힘). 틀린 사실을 넣는 가짜 LLM은 1회 Guard 통과율 0%로 나옵니다. 지표가 차이를 잡는다는 확인입니다.
- 사람 평가(보고서 10개 × 3문항)는 이 묶음에 없습니다.

## 7-1. 정적 배포본 질문창 (Gemini, 무료 등급)

배포본(Vercel)에는 에이전트 서버가 없어서, 첫 화면 ④ 질문창만 작은 서버 함수(`web/api/chat.ts`)가 Gemini에 묻습니다. 규칙은 `web/src/lib/geminiChat.ts` 한 곳에 있습니다.

| 단계 | 하는 일 |
|---|---|
| 요청 검사 | 질문 300자 안, 기준일(2025년)·도시(강남·춘천) 형식 확인 |
| 근거 고르기 | 서버가 자기 배포본의 `/data/home/<기준일>_<도시>.json`을 직접 읽음. 화면이 보낸 근거는 쓰지 않음. 고른 동의 후보(없으면 등급 높은 후보 5개)와 요약만 넘김 |
| 지시문 | 근거 안 내용만, 숫자·지역·기관을 지어내지 않음, 등급을 바꾸지 않음, 개인 진단 금지, 4문장 이내 |
| 답 검사 | 근거에 없는 숫자가 든 문장은 뺌(뺀 수를 화면에 표시). 다 빠지면 답을 보이지 않음 |
| 무료 한도 | 결제수단이 없는 키라 한도를 넘으면 과금 대신 429. 429면 다른 모델로 넘기지 않고 "오늘 무료 질문 한도가 찼어요"로 멈추고, 그 브라우저는 그날 다시 부르지 않음(근거 카드 답으로 대신) |
| 키 | Vercel 환경 변수 `GEMINI_API_KEY`에만 둠. 레포·화면 빌드에 넣지 않음 |

- 실측(2025-09-26 춘천, 조운동): "왜 먼저 봐야 해?"에는 근거 카드의 등급 이유·할 일로 답했고, "주민 몇 명이 고립돼 있어?"에는 "이 화면 근거로는 알 수 없습니다"라고 답했습니다. 표본이 작아 품질 평가(§7)에는 넣지 않았습니다.
- 질문은 국외(Google API)로 전송됩니다. 배포본 질문창에는 개인정보를 적지 말라고 안내하고, 근거 JSON에는 개인정보가 없습니다.

## 8. 한계

- 설명 문장의 자연스러움은 모델에 따라 달라질 수 있습니다. 등급과 숫자는 달라지지 않습니다.
- 개인정보를 가린 질문이 국외(Anthropic API)로 전송됩니다. 가리기는 정해진 패턴(전화번호·주민번호·이메일·상세 주소·사람 이름의 몇 가지 모양)만 잡으므로 다른 식별 정보(별명, 이름만 쓴 말, 드문 표기, 가족관계·직업으로 특정되는 설명 등)는 빠질 수 있습니다. 자동 가리기는 개인정보를 줄이는 장치이지 모두 지운다는 보장이 아닙니다. 공공기관 배포 시에는 LLM 없이 도는 모드를 기본으로 두고, 승인을 받은 뒤 LLM을 켭니다.
- 프롬프트를 고치면 파일 이름의 버전을 올리고(`explain_v1` → `explain_v2`) 적대 테스트를 다시 돌립니다. 쓰는 판은 `configs/llm.yaml`이 정하고, 예전 판은 비교용으로 `configs/prompts/`에 남겨 둡니다.
