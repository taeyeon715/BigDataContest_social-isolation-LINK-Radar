# LLM 활용 설명

대회 규정에 따라 LINK-Radar에서 생성형 AI(LLM)를 **어디에, 어떻게, 어디까지** 쓰는지 정리한 문서입니다. 코드 기준은 `src/bigcontest/agent/llm.py`, 설정은 `configs/llm.yaml`, 프롬프트는 `configs/prompts/`입니다.

## 1. 한 줄 원칙

**판단은 코드, 설명은 LLM.** 후보·등급·근거 숫자는 Python 코드와 규칙 파일(`configs/*.yaml`)이 정합니다. LLM은 담당자의 질문을 해석하고, 추가로 볼 자료를 고르고, 근거를 쉬운 문장으로 풀어 쓰는 일만 합니다. LLM이 꺼져 있어도 같은 등급과 보고서(템플릿 문장)가 나옵니다.

## 2. 사용 모델

| 용도 | 모델 | 이유 |
|---|---|---|
| 질문 해석, 추가 조사 선택, 설명 문장 | Claude Sonnet 5.5 (`claude-sonnet-5-5`) | 한국어 이해, 구조화 출력(JSON 스키마) 안정성 |
| 정기 감시 대량 브리핑 | Claude Haiku 5.5 (`claude-haiku-5-5`) | 짧은 요약을 많이 만들 때 비용이 낮음 |

- 모델 ID와 가격은 `configs/llm.yaml` 한 곳에만 둡니다(가격: Anthropic 공식 가격표, 2026-10-13 확인).
- 출력은 모두 **JSON 스키마 구조화 출력**으로 받고 Pydantic으로 다시 검사합니다. 형식이 틀리면 1회 다시 묻고, 그래도 실패하면 규칙 기반·템플릿으로 대신합니다.

## 3. LLM이 하는 일 (여섯 자리)

| 자리 | 입력 | 출력 | LLM이 없을 때 | 프롬프트 |
|---|---|---|---|---|
| 질문 해석 (`classify`) | 담당자 질문 (개인정보 가린 뒤) | 경로(조회/조사/범위 밖), 정규화한 요청(도시·집단·기간·지표) | 규칙 기반 분류 | `classify_v2` |
| 추가 조사 선택 (`choose_extra_tools`) | 정규화한 요청, 쓸 수 있는 도구 목록 | 추가로 부를 도구 이름 (허용 목록 안에서만) | 추가 조사 없음 | `choose_tools_v1` |
| 설명 문장 (`explain`) | 근거 카드 요약 (근거 ID·지표·방향) | 쉬운 설명 문장 2~4개, 근거 ID 인용 | 템플릿 문장만 | `explain_v4` |
| 정기 감시 브리핑 (`brief`) | 후보 목록 요약 | 짧은 브리핑 문장 | 템플릿 문장만 | `brief_v3` |
| 추가 조사 계획 (`plan_more`) | 담당자가 고른 범위와 메모 (개인정보 가린 뒤) | 도구·반증 계획 (허용 목록 안에서만) | 메모 낱말 규칙 | `plan_more_v1` |
| 이어 묻기 (`followup`) | 보고서 근거 카드와 질문 | 근거 ID만 인용하는 설명 문장 | 템플릿 문장만 | `followup_v2` |

## 4. LLM이 하지 않는 일

- **등급·후보를 정하지 않습니다.** 필수 근거 도구는 LLM이 고르지 않아도 항상 실행되고, 등급은 규칙이 계산합니다. 가짜 LLM 6종, 실제 Claude, LLM 없음의 세 경우 모두 시연 사례 D1~D4의 등급이 같다는 테스트가 있습니다(`tests/test_determinism.py`, `tests/test_demo_cases.py`).
- **숫자를 만들지 않습니다.** 보고서의 숫자·사실 문장은 근거 카드에서 템플릿으로 넣습니다. LLM 설명 문장에 숫자(한글 수량 포함)나 근거에 없는 사실이 들어가면 Guard가 수정(REVISE)을 요구하고, 두 번 넘게 반복되면 보류합니다.
- **개인을 찾거나 판정하지 않습니다.** 개인을 지목하는 질문은 LLM에 보내기 전에 코드가 범위 밖으로 처리합니다.
- **원천 데이터를 보지 않습니다.** LLM에는 집계된 근거 카드 요약만 들어가고, 카드·통신 원자료와 자원 원장 원문은 들어가지 않습니다.
- **경로를 함부로 바꾸지 않습니다.** 규칙이 정한 조사 경로를 LLM이 낮출 수 없습니다.

## 5. 안전장치

| 장치 | 내용 |
|---|---|
| 계약 검사 | 데이터에 없는 조합(예: 연령 × 시간대), 기준일 뒤 자료는 LLM 호출 전에 코드가 보류 |
| 개인정보 가리기 | 질문을 보내기 전 전화번호·주민번호·주소(번지·호)·호칭이 붙은 이름을 가림. 가린 개수만 기록 |
| 보고서 Guard | 사실 검사(지표·지역·기간·값·단위·방향·근거 ID 대조)와 표현 검사(거주민 단정, 진단 문장, 정확도 주장, 지표를 다른 뜻으로 바꾸기) |
| 적대 테스트 | 개인 지목·주입 문구 질문, 방향 바꾸기·한글 수량·반어 부정 문장을 묶은 테스트 세트 |
| 재시도 한도 | Guard 수정 요구 최대 2회, 넘으면 판단 보류 |

## 6. 비용과 기록

- 호출마다 모델 ID, 프롬프트 버전, 입력·출력 토큰, 소요 시간, 비용(USD)을 실행 기록에 남깁니다. API 키와 질문 원문은 기록하지 않습니다.
- 시험 실행 기준: 조사 1회에 호출 3~5번, 약 $0.01~0.06, 13~21초. 에이전트 연결 시험 전체는 18회, 약 $0.15였습니다.
- 실제 API를 부르는 테스트는 `RUN_LLM_TESTS=1`일 때만 돌고, 평소 테스트는 네트워크를 쓰지 않습니다.

## 7. 한계

- 설명 문장의 자연스러움은 모델에 따라 달라질 수 있습니다. 등급과 숫자는 달라지지 않습니다.
- 질문 원문이 국외(Anthropic API)로 전송됩니다. 공공기관 배포 시에는 LLM 없이 도는 모드를 기본으로 두고, 승인을 받은 뒤 LLM을 켭니다.
- 프롬프트를 고치면 파일 이름의 버전을 올리고(`explain_v1` → `explain_v2`) 적대 테스트를 다시 돌립니다. 쓰는 판은 `configs/llm.yaml`이 정하고, 예전 판은 비교용으로 `configs/prompts/`에 남겨 둡니다.
