# 숫자 사용 기준

발표·보고서·README에 숫자를 쓸 때 지키는 기준입니다. 숫자마다 **모집단·조건·단위**를 붙여야 하고, 붙이지 않으면 다른 주장이 됩니다. 2026-10-14 외부 점검(커밋 8b0ae2e, §4)에서 재현을 확인한 숫자를 모았습니다. 노트북을 다시 돌려 값이 바뀌면 링크한 리포트가 기준입니다.

## 2. 쓰지 않는 표현

현재 근거로는 아래 문장을 쓰지 않습니다.

- "개인의 고립을 90% 탐지한다", "PR-AUC 0.97로 실제 고립을 예측한다."
- "2025년에 남면의 고립 위험을 사전 예측했다", "Level 3는 고립 확률이 높다는 뜻이다."
- "정답 자원 75%를 찾았다", "추천이 75% 정확하다", "부적격 0이므로 모두 이용 가능하다."
- "65세 이상 독거가구 1,854세대", "새로 고립된 9명/9개 동을 찾았다."
- "어떤 LLM 선택/어떤 추가 근거 오류에도 등급과 실행 끝 상태가 같다." (정상 자료에서 같은 등급인 것만 시험함. 추가 근거가 Guard에 걸리면 실행 전체를 보류)
- "자유 글의 개인정보가 모두 제거되고 DB·체크포인트에 절대 남지 않는다." (자동 가리기는 정해진 형식만 잡음)
- "가상 세계의 감지 비율·순위 상관이 실제 현장 성능을 입증한다."
- "동 수 68% 감소로 실제 업무시간 68% 절감." (시간 절감은 동당 시간을 가정한 시나리오로만)
- "집계 자료만 쓰므로 개인 동의·결합 없이 바로 도입할 수 있다." (분석 입력이 집계 자료라는 뜻일 뿐, 기존 명단 활용은 기관의 승인된 절차 안에서)
- "규칙 임계값은 모두 사전 설정이다." (값별 설정 시점은 [위험 지표 정의서](위험_지표.md) 7절)

## 3. 쓰는 방법

- 숫자 옆에 단위를 씁니다: 동 / 행 / 후보 행 / 코호트 / 쌍 / 명 / 세대.
- 합성이면 "합성"을, 탐색적이면 "탐색적"을, 결과를 보고 정한 값이면 "사후"를 붙입니다.
- 관측일 기준 시간과 공급 지연을 넣은 재생 시간을 구분합니다.
- 서로 다른 분모(예: 90%와 93%)를 한 숫자로 합치지 않습니다.
