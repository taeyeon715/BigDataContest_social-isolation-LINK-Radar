# 데이터 설명

## 한눈에 보기

| | SK텔레콤 유동인구 | 신한카드 결제 |
|---|---|---|
| 내용 | 어느 장소에 어떤 사람이 언제 머물렀나 | 어느 업종에서 어떤 고객이 언제 얼마를 썼나 |
| 장소 | 50m × 50m 칸 | 강남구, 춘천시 2곳 |
| 시간 | 월 (6개월) | 일 (184일) |
| 파일 | 성연령·시간대·요일 파일 × 6개월 = 18개 | 데이터1, 데이터2 |

두 데이터가 같이 맞물리는 단위는 **도시 × 성별 × 연령대 × 월**뿐입니다.

## SK텔레콤 유동인구

파일 3종류 (서로 합칠 수 없음)

| 파일 | 내용 | 주요 컬럼 |
|---|---|---|
| `flow_age_pop` | 성별·연령대별 | `MAN_FLOW_POP_CNT_10G` ~ `60GU` (남), `WMAN_...` (여) |
| `flow_time_pop` | 시간대별 (0~23시) | `TMST_00` ~ `TMST_23` |
| `flow_wkdy_pop` | 요일별 | `FLOW_POP_CNT_MON` ~ `SUN` (화요일은 `TUS`) |

공통 컬럼: `STD_YM`(년월), `BLOCK_CD`(지역코드), `X_COORD`, `Y_COORD`(좌표, UTM-K)

- `BLOCK_CD` 앞 5자리 = 시군구 (`11230` 강남, `32010` 춘천), **앞 8자리 = 행정동**
- 값은 하루 평균 유동인구(보정된 추정값). "몇 명"보다 "얼마나 붐볐나"로 보기
- 60대 이상은 한 묶음 (70·80대 구분 없음)
- 연령 파일과 시간대 파일이 따로라서 "60대가 밤에 얼마나" 같은 분석은 불가
- 12월 시간대·요일 파일은 모든 행이 2번씩 들어 있음 → 중복 제거 (주최측 공지)

## 신한카드 결제

| 파일 | 용도 | 있는 것 | 없는 것 |
|---|---|---|---|
| 데이터2 | **주제 2용, 주력** | 고객 거주 시도 | 시간대 |
| 데이터1 | 주제 1용, 보조 | 시간대 4구간 | 고객 거주지 |

컬럼: `TA_YMD`(날짜), `TIME_GB`(시간대, 데이터1만), `MCT_SGG_CD`(가맹점 지역), `MCT_RY_CD`(업종), `CLN_SGG_CD`(고객 거주 시도, 데이터2만), `SEX_CCD`(성별), `AGE_CCD`(연령대), `TS_AT`(결제금액), `USE_CNT`(결제건수)

주의할 점
- **두 파일을 더하면 안 됨** (데이터2는 데이터1 개인 결제를 거주지별로 나눈 것)
- 결제건수·금액은 연령마다 다른 배율이 곱해진 값 → 연령끼리 직접 비교하지 말고 비율로 보기
- 데이터1에 법인카드가 섞여 있음 → 개인 분석에서 제외
- 쇼핑몰·보험·세금 같은 업종은 본사 주소로 잡힘 → 제외 (`categories.py`)
- 가맹점 위치 ≠ 고객 거주지

## 외부 데이터

출처·라이선스 전체 표는 `external/README.md`, `NOTICE.md`에 있습니다. 여기서는 분석에 쓰는 기준만 적습니다.

### 공휴일

- 목록: `configs/project.yaml` `holidays` (2025-07~12, 8일: 8/15, 10/3, 10/5~10/9, 12/25)
- 출처: 한국천문연구원 천문우주지식정보 「2025년 월력요항」 (https://astro.kasi.re.kr/kor/life/post/calendarData?year=2025). 월력요항은 우주항공청이 천문법에 따라 관보에 싣는 달력 기준 자료입니다.
- 대조: `uv run python -m bigcontest.holidays` → `external/holidays/공휴일_2025-07_12.csv`. 설정 목록과 날짜가 같은지 테스트(`tests/test_external_sources.py`)로 확인합니다. 페이지 사본은 `external/holidays/raw/`(git 추적 안 함).
- 공공데이터포털 특일 정보 API(15012690)는 이 키로 활용 신청이 안 되어 있어(403) 쓰지 않았습니다. 월력요항 뒤에 정한 임시공휴일은 들어 있지 않습니다. 2025-07~12에 따로 정한 임시공휴일은 확인하지 못했습니다.

### 날씨 (기상청 ASOS 일자료)

- 관측소: 서울 108(강남 대표), 춘천 101. 기간 2025-07-01~12-31, 184일 × 2
- 강수량 빈 값 = 0 (무강수일). 다른 칸 빈 값은 결측
- 원문 JSON: `external/weather/raw/asos-<시각>/` (git 추적 안 함). 실행 기록 `external/weather/수집_기록.csv`
- 다시 만들기: `uv run python -m bigcontest.weather --offline` (원문 → CSV). 새로 받은 값이 지금 CSV와 다르면 CSV를 바꾸지 않습니다(`--write`일 때만)

### 기상특보는 받지 않음 — ASOS 일자료로 근사

기상청 기상특보 자료는 받지 않았습니다. R4·R6 트리거는 ASOS **일자료**에 아래 기준을 대어 근사합니다(`src/bigcontest/agent/tools/signal.py` `WARN_RULES`, R4 단계는 `configs/rules.yaml` `thresholds.heat`와 `src/bigcontest/rules/heat.py`). 탐색용 폭염 반응(`calc_heat_response`)은 예전처럼 최고기온 33℃ 이상 날을 씁니다. 특보 발표 기준과 같지 않으므로 "특보 발효"라고 말하지 않습니다.

| 이름 | 쓰는 칸 | 이 프로젝트 기준 (일자료) | 기상청 특보 기준 (주의보, 참고) | 2025-07~12 해당 날 |
|---|---|---|---|---|
| 폭염 (R4, rules-v1.1) | `at_max` 일 최고 체감온도 근사 (`weather/kma_asos_heat_2025-07_12.csv`, 기상청 여름철 체감온도 식에 일 최고기온·일 최소 습도) | 주의보: 체감 ≥ 33℃ 2일 연속 / 경보: ≥ 35℃ 2일 연속 / 중대경보: 체감 ≥ 38℃ 또는 기온 ≥ 39℃ 하루 | 주의보 체감 33℃·경보 35℃ 2일 이상 지속 예상, 중대경보(2026 신설) 체감 38℃ 또는 기온 39℃ | 체감 33℃ 이상 강남 24일, 춘천 21일 (예전 기준 최고기온 33℃ 이상은 25일·30일). 단계별 날 수는 `reports/r1_등급규칙` 7-3 |
| 호우 (R6) | `rain` 일강수량 | ≥ 80mm | 3시간 60mm 이상 또는 12시간 110mm 이상 예상 | 강남 7/19·8/13, 춘천 7/20 |
| 대설 (R6) | `snow_new` 일 신적설 | ≥ 5cm | 24시간 신적설 5cm 이상 예상 | 강남 12/4 |
| 한파 (R6) | `tmin` 최저기온 | ≤ −12℃ | 아침 최저 −12℃ 이하가 2일 이상 지속 예상 등 | 춘천 12/4·12/26·12/27 |

- 특보는 **예상**을 보고 발표하고, 여기서는 그날 **실측** 일값을 봅니다. 시간 단위 강수(3·12시간)도 보지 않습니다.
- 기준일 뒤 실측을 쓰는 트리거는 "상황 시연"으로 표시하고 성능 평가에서 뺍니다.
- 특보 기준 참고: 기상청 날씨누리 특보 기준 (https://www.weather.go.kr/w/weather/warning/standard.do)

### 복지자원 좌표

- 주소가 있는 자원의 좌표는 **도로명주소 좌표제공 API(juso.go.kr)**의 건물 출입구 좌표입니다(2026-10-18, `coord_source` = 도로명주소 좌표제공 API, `coordinate_status` = 확인(juso)). 만드는 법: `uv run python -m bigcontest.resources.juso collect`(검색 API로 주소 → 건물 키, 좌표 API로 건물 키 → UTM-K 좌표, 위경도로 변환) → `apply`(원장에 반영, 행정동 다시 배정). 키 없이 다시 만들기: `offline`(raw 원문에서).
- 주소 830개 중 819개(98.7%)가 하나의 건물로 정해졌습니다. 시군구·도로명·건물번호(지번이면 동·번지)가 모두 같은 결과가 하나일 때만 씁니다. 건물번호가 도로명주소에 없거나(9개) 여러 건물이 걸린(2개) 주소는 좌표를 바꾸지 않았습니다.
- 원래 원장 745건: 지오코더(ArcGIS·Photon) 좌표 733건 중 723건을 바꿨고, 10건은 ArcGIS 탐색용 좌표에 "도로명주소 미매칭"을 붙여 남겼습니다(강남노인종합복지관, 춘천종합사회복지관 등. 주소를 고쳐 다시 찾을 대상). 원천 제공 위경도 5건은 그대로입니다. 보강 자원은 지오코더 좌표를 빌린 3건과 좌표가 없던 고용센터 2건을 도로명주소 좌표로 채웠고, E-Gen 좌표 277건은 그대로입니다.
- 바뀐 거리: ArcGIS → 도로명주소 725건의 이동은 중앙값 1m, 95% 147m, 최대 565m(아파트 단지 경로당이 단지 출입구로 옮겨 감). 500m 넘게 옮긴 곳은 1건(미도아파트 경로당 565m), 2km 넘는 곳은 없습니다. 행정동이 바뀐 곳은 3건입니다: 한림대 춘천성심병원 후평1동→교동, 춘천마음숲정신건강의학과 소양동→조운동(둘 다 주소의 법정동과 맞게 됨), 강남 더샵 시니어하우스 경로당 수서동→일원본동(출입구가 경계 옆, 검토 대상).
- 비교용으로 원천 좌표도 도로명주소와 맞춰 봤습니다. 원천 제공 위경도 8건은 0~90m로 같았고, E-Gen 277건은 중앙값 1m지만 6건이 500m 넘게 달랐습니다(춘천 동면 약국 2곳 4~5km, 퇴계동 약국 2.7km, 개포자이 상가 3곳 0.6km). E-Gen 좌표는 원천 값이라 바꾸지 않았고 탐색용으로 남깁니다. 모든 비교는 `external/resources/좌표_교체_기록.csv`(좌표 없이 이동 거리·행정동만).
- 좌표 변환: UTM-K(EPSG:5179) → 위경도는 `resources/juso.py` `utmk_to_wgs84`(횡메르카토르 역변환). pyproj 결과와 0.2mm 안에서 같습니다.
- 원장은 원본 12개에서 다시 만들 수 있습니다: `uv run python -m bigcontest.resources.build_ledger` (원본은 `external/resources/raw/원장_원본/`, SHA256은 `원본_출처목록.csv`). 좌표는 `좌표_도로명주소.csv`에서 주소로 찾고, 하나로 정해지지 않은 주소만 지금 원장 좌표를 씁니다(지오코더는 다시 돌리지 않음). 다른 좌표를 쓰려면 `build(coords=...)`.
