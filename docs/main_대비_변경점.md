# main 대비 변경점 (taeyeon/rules-v2)

`origin/main`(4843f0d)과 `taeyeon/rules-v2` 브랜치의 차이를 정리했습니다. 이 브랜치에는 준서의 `integration/demo-readme-20261022`(T1.5·T3·README)도 병합되어 있으므로, 아래에는 그 내용도 함께 들어 있습니다.

## 한 줄 요약

등급 규칙을 rules-v1.1(동 × 정책 집단, 동 전체 1인세대 비율과 거점 거리로 등급)에서 **rules-v2.0(동 × 성 × 연령 470칸, 신한카드·SK 통신 신호로만 등급)**으로 바꾸고, 에이전트 전체를 이 규칙으로 돌게 했습니다. 공공 자료(주민등록·수급 통계·자원 원장)는 확인과 순서에만 씁니다.

## 1. 왜 바꿨나

| 문제 (v1.1) | 바꾼 방식 (v2.0) |
|---|---|
| 고령층과 중장년 남성이 같은 동을 받음 (S1이 전 연령 동 비율 하나) | 칸마다 그 성·연령의 신호로 판단 |
| 여성은 정책 집단에 없어 보이지 않음 | 470칸에 남녀 모두. 순위는 같은 도시·성·연령 안에서만 매겨 한쪽이 다른 쪽에 묻히지 않음 |
| 외부 자료(1인세대 비율·거점 거리)만으로 Level 2·3이 나옴 | 등급은 신한·SK 신호로만. 외부 자료는 확인·순서 |
| 연휴 트리거가 모든 집단에 같게 걸림 | 공휴일 분석(R-3b)으로 연휴에 실제로 끊기는 60대 이상 칸에만 |
| 춘천 읍·면 전체 겨울 값 하나로 모든 읍·면이 동절기 근거를 받음 | 읍·면마다 겨울 체류 감소를 따로 확인 |
| 카드 이탈 기준(−2.5, 3일, 10%)이 EDA-6 사후 기준 | LINK-Sim 합성 정답으로 고르기·평가를 나눠 골랐음 (−2.0, 4일, 5%) |
| 태연 2축 결과가 2025.12 사후 값이라 기준일 판단에 못 씀 | 태연 H(체류도 보정)를 기준월별로 계산하는 모듈로 옮겨 기준일에 공개된 달만 씀 |

## 2. 등급 규칙

| | rules-v1.1 | rules-v2.0 |
|---|---|---|
| 단위 | 행정동 × 정책 집단 4개 | 행정동 × 성 × 연령(20·30·40·50·60대 이상) 470칸 |
| 등급 신호 | S1 동 1인세대 비율, A1 거점 거리 | H 행동 고립(SK), W 읍·면 겨울 체류 감소(SK), C 카드 결제 공백(신한) |
| 확인용 | — | S 칸 1인 비율, V 경제 취약, A 거점 거리 |
| Level 3 | 트리거 + S1 상위 + A1 5km 이상 | 트리거 + 신한·SK 신호 2개 이상 + 공공 자료 확인 1개 이상 + 충족 + 신뢰도 보통 이상 |
| Level 2 | S1 상위 또는 A1 원거리 + 트리거/이탈 | 동을 가리키는 통신 신호(H 또는 W) 1개, 또는 반증 통과 카드 이탈(먼저 볼 동에 H) |
| Level 1 | 근거 하나뿐 등 | 통신 신호 없음(카드 신호만·공공 자료만), 기각, 하락 5% 미만 |
| 후보에 드는 동 | S1 상위 또는 A1 원거리 동 | 칸 판정으로 Level 2 이상인 동 (v1.1 진입 동은 Level 1로 남음) |
| 청년 남성 | 도시 단위 안내 1건 | 다른 칸과 같은 규칙 (예외 없음) |
| 카드 이탈 기준 | z −2.5, 7일 중 3일, 10% | z −2.0, 7일 중 4일, 5% |
| 신호 검증 | — | 강남 시민생활과 방향이 확인되지 않은 신호(성·연령별)는 Level 3 근거에서 뺌 (`configs/signal_check.csv`, 화면에 '방향 미확인') |

설정은 [`configs/rules_v2.yaml`](../configs/rules_v2.yaml), 판정은 [`src/bigcontest/rules/levels_v2.py`](../src/bigcontest/rules/levels_v2.py). 값마다 정한 시점([사전 설정] / [자료 노출 후] / [LINK-Sim] / [결과 후 결정])을 주석으로 달았습니다.

**에이전트**

- 도구 `get_holiday_watch`(연휴 주의 기간에만), `get_winter_cells`(춘천 동절기에만)를 실제 도구로 추가.
- `assign_level` 노드: v1.1 판정 → 연휴 주의 → 동절기 칸 → 칸 판정 일괄 전환 순서.
- 데이터 소스 경보 패널이 규칙 판에 맞는 기준을 씀 (`rules.version.alarm_config`).
- 후보 카드 참고 칸(준서 T3)의 내용을 태연 2025.12 사후 단계(심각~정상)에서 **기준일 계산 칸 근거 축**으로 바꿈. 사용자에게 보이는 척도는 Level 0~3 + 판단 보류 하나.
- `Report.holiday_watch` 필드 추가 (연휴 주의 블록).
- `guard.fmt_value`: 유효숫자 6자리 절삭으로 10만 넘는 소수 값이 사실 대조에서 어긋나던 버그 수정(청년 남성 질문이 보류되던 원인, v1.1에서도 재현됨).
- 1인세대 성·연령 자료는 준서 파일·함수(`resident_single_by_age`) 하나로 통일 (태연이 넣은 10세 구간 파일과 칸 2,820개 값이 같음을 확인 후 삭제).

**화면**: `StructuralRisk.tsx`가 칸 근거 축(선 신호·유형·값)을 보여 줌. 타입 `StructuralRiskReference.cells` 필드 변경.

- 참고: 이전에는 `tests/test_t1_5.py` 가 노트북을 불러오며 `LINKRADAR_RULES=v1.1` 을 프로세스 전체에 남겨, 전체 시험에서 카드 경보가 v1.1 기준(7일 중 3일)으로 돌았습니다. 노트북을 불러온 뒤 되돌리게 고쳤고, 그 때문에 기대값이 달라진 시험 2개(D3B 강남 추석 뒤 경보, 춘천 20대 여성 경보 직후)를 v2.0 결과로 맞췄습니다
- v2로 기대값을 바꾼 시험: 시연 D1(강남 중장년 남성 후보 11개, Level 3 없음), D2(동절기 후보 8개, Level 3 남산면·동산면), 대시보드·API D2, 춘천 9/26 근거 ID, 추가 조사 범위. 바꾼 이유를 시험 주석에 적었습니다.

## 7. 준서가 봐 줬으면 하는 것

1. 공식 등급을 v2.0으로 바꾸는 데 동의하는지. main의 R-1·R-2 리포트는 v1.1 결과로 그대로 두었습니다(재현 노트북은 v1.1 고정).
2. 후보 수가 늘었습니다(9/26 정기 감시 17건 → 28건, Level 3는 8건). Level 2가 통신 행동 고립 상위 동이라 연휴에는 도시 동의 약 1/3입니다. 화면에서 Level 2를 접어 둘지.
3. 질의응답에서 정책 집단(고령층 65세 이상 등)과 칸(60대 이상 등) 연령 경계가 다릅니다. 카드 참고 칸에 대응 설명을 붙였지만 문구 검토가 필요합니다.
4. LLM 설명 프롬프트에 v1.1 표현이 남아 있는지 (규칙 판 꼬리표 `[rules-v1.1]`이 일부 문장에 남아 있음).
5. README 후보 상세 캡처(`docs/images/readme/candidate.png`)는 옛 화면이라 다시 찍어야 합니다.

## 8. 한계

- 연휴에 끊기는 연령(60대 이상)은 2025 추석 한 번의 관측으로 정했습니다. 2026 설 연휴로 다시 확인해야 합니다. 결제 감소가 가족과 함께 있어서인지 실제 공백인지 구분하지 못합니다.
- 결과를 본 뒤 정한 규칙: 연휴 연령, 카드 신호 기준(−5%p), Level 3의 공공 자료 확인 조건, Level 2에 통신 신호 요구, 동절기는 통신 신호 둘로 셈. 모두 R-3 README에 비교와 함께 적었습니다.
- 카드는 도시 × 성 × 연령이라 동을 가리키지 못하고, 통신 연령은 60대 이상이 한 묶음입니다.
- S(1인 비율)는 작은 동일수록 높게 나옵니다(춘천 −0.58). 확인용으로만 써서 영향은 줄였습니다.
- 신호 방향 확인(R-3c)에서 H는 10개 성·연령 중 6개, S는 6개가 확인입니다(20·30대 대부분 미확인). 미확인 신호는 Level 3 근거에서 빼지만, 기준 자료가 추정치이고 강남 22개 동뿐입니다.
- 실제 고립 정답이 없어 정확도는 말할 수 없습니다. 접근성은 2026년 원장 기준입니다.
